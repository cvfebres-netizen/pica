## ✅ Feito (implementado e validado)

### Arquitetura e stack
- Estrutura de pastas criada (`src/`, `test/`, `scripts/`, `docs/`, `prompts/`)
- LEIA-ME com arquitetura e decisão de interligação
- Stack: Node.js + Baileys (WhatsApp local, sem browser, gratuito) + Google Calendar API v3 + JSON local para pendentes/escalation
- `package.json` com scripts (`start`, `simular`, `ligar-google`, `lembretes`, `painel`)
- `node --check` OK em todos os ficheiros editados/novos
- Commit e push efetuados (`e2f802b`, branch `main`, sincronizado com `origin/main`)


### Gateway WhatsApp (`src/gateway/baileys-gateway.js`)
- Conexão Baileys com autenticação local (sem browser)
- Leitura de QR code para emparelhar telemóvel
- Reconexão automática e deteção de mensagens próprias (evita loop)
- Modo mononúmero: clínica = gestor (mesmo número `351932290927`); não envia aviso para si mesmo; aceita OK/NÃO de qualquer remetente com pendente

### Formulário passo a passo (`src/atendimento/formulario.js`)
- FSM: nome → telefone → animal → espécie → serviço → data/hora → confirmação
- Estado por cliente guardado em `src/dados/formulario-estados.json`
- Lista de serviços dinâmica (consulta, vacina, desparasitação, banho, tosquia, análises)
- Quando concluído, cria PENDENTE para aprovação do gestor e avisa o gestor
- Cliente recebe confirmação de envio e aguarda OK/NÃO

### Histórico de atendimentos (`src/atendimento/historico.js`, `src/dados/historico.json`)
- Registo de cada agendamento aprovado (cliente, serviço, animal, espécie, data/hora, estado)
- `Historico.registar()`, `Historico.listar(cliente)`, `Historico.ultimo(cliente)`, `Historico.todos()`
- Usado pelo painel web e pelo roteador (após aprovação do gestor)

### Lista de espera (`src/atendimento/listaEspera.js`, `src/dados/listaEspera.json`)
- Quando um horário está ocupado (CONFLITO), o cliente é adicionado à lista de espera
- `ListaEspera.adicionar()`, `ListaEspera.listar()`, `ListaEspera.atender(id)`, `ListaEspera.proximo(servico)`
- Usado pelo roteador em caso de conflito de horário

### Múltiplos calendários (`src/agenda/google-calendar.js`)
- `CAL_ID(servico)` resolve calendar ID por serviço via env `GOOGLE_CAL_CONSULTA`, `GOOGLE_CAL_VACINA`, etc.
- Fallback para `GOOGLE_CALENDAR_ID` / `primary` se não houver entrada específica
- Todas as funções (marcarProvisoria, confirmarEvento, apagarEvento, marcarConsulta, cancelarConsulta, remarcarConsulta, horarioLivre) aceitam parâmetro `servico`

### Roteador e respostas (`src/atendimento/roteador.js`, `respostas.js`)
- Roteador de intenções: marcar / remarcar / cancelar / dúvida / urgência
- Respostas curtas em PT-PT sem rodeios
- Transcrição de áudio stub integrada no gateway (`src/atendimento/transcricao.js`)

### Serviços e regras de negócio (`src/atendimento/servicos.js`)
- Tabela de serviços: consulta, vacina, banho, tosquia, cirurgia, desparasitação, análises
- Cada serviço com duração, preço, contacto direto, horários preferenciais, não sobreposição
- Cirurgia requer contacto direto (não cria evento; avisa para ligar)
- Banho/tosquia só aceitam 10:00 ou 14:30; senão avisa horário preferencial
- Duração mínima tosquia: 90 min
- Não sobrepõem entre si (banho e tosquia)
- Urgência: avisa para ligar já, não cria evento

### Google Calendar (`src/agenda/google-calendar.js`)
- Criar/mover/apagar/listar eventos
- Verificação de conflito (`horarioLivre`): `marcarProvisoria` lança `CONFLITO` se houver evento ocupado
- Eventos criados como provisórios (pendentes de aprovação do gestor)
- Suporte a múltiplos calendários por serviço

### Pendentes e aprovação (`src/atendimento/pendentes.js`, `src/dados/pendentes.json`)
- Registo de agendamentos provisórios aguardando OK/NÃO do gestor
- Modo mononúmero: aceita OK/NÃO de qualquer remetente com pendente
- Exporta `ler()` para uso do painel web

### Lembretes 24h antes (`src/agenda/lembretes.js`, `scripts/lembretes-diarios.js`)
- Script `npm run lembretes` envia lembretes do dia seguinte
- Pronto para ser colocado no SO cron (diário 09:00)

### Escalation (`src/atendimento/escalation.js`, `src/dados/escalation.json`)
- Após 2 mensagens não percebidas, avisa o gestor
- Registo de falhas por número de telefone

### Áudio (`src/atendimento/transcricao.js`)
- Stub de transcrição de áudio integrado no gateway (preparado para whisper.cpp local ou OpenAI Whisper API)

### Painel web (`src/web/panel.js`, `npm run painel`)
- Express na porta 3000 (configurável via `PORT`)
- GET `/` — dashboard com pendentes e lista de espera
- GET `/historico` — histórico de atendimentos
- GET `/lista-espera` — lista de espera com botão "Atendido"
- POST `/pendente/:id/aprovar` e `/pendente/:id/recusar`
- HTML simples, sem dependências front-end

### Simulador e testes (`test/simulador.js`, `test/stress-test.js`)
- Simulador sem WhatsApp nem Google Calendar: 11/11 testes OK
- Stress test: 375 asserts por execução, 3 execuções = 1125 asserts totais, 0 falhas
- Cenários cobertos: mensagens válidas, nonsense/escalation, gestor aprova/recusa, loop de bloqueio (10 nonsense seguidos), formulário passo a passo, NÃO na confirmação, serviços (cirurgia vs consulta), horários preferenciais banho/tosquia, urgência, casos extremos (strings vazias, emojis, 500 chars), histórico, lista de espera, múltiplos clientes interleave

- `scripts/instalar.bat` (instalação no PC da clínica)
- `docs/ligacao-passo-a-passo.md`
- `prompts/agente-atendimento.md`
